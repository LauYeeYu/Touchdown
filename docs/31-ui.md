# 31 UI

Pages and the main flows. Layout details come later; this fixes what each page must do.

The app is responsive: every page works in Chrome on Android. iOS is not a target. It has light and dark themes (G10), and all copy uses UK English (G9). The quick-add flows are designed for phone first, because sightings are often logged at the airport.

## Navigation

```
Home | Flights | Sightings | Aircraft | Stats | Map | Import | Issues | Settings
```

## Period control

Home, Flights and Stats share one period control.

- Segmented buttons (outlined pill, equal-width segments, a check on the selected one) while they fit, at most five segments: the most recent years, then "All time".
- Older years move into an "Earlier" segment that opens a menu; picking one shows that year in the segment.
- On very narrow screens the control becomes a single menu button listing every period.
- The selected segment is shown by fill and check, not by bolder text, and every segment reserves room for its longest label, so the control never changes width when the selection changes.

## First run

0. The Access gate asks the user to sign in (Google or a one-time email code). Only invited users get past it (U3).
1. Choose storage: Google Drive, local folder (desktop Chromium only), or "this browser only + manual export".
2. Google Drive: sign in, the app creates the `Touchdown/` folder (or finds an existing one it created before).
3. Offer import of existing data (FR24 CSV, Google Sheets, generic CSV).

## Home

- Flights summary tiles: flights, distance, time, airports, airlines, aircraft.
- Sightings summary tiles: aircraft, sightings, airlines, families, type codes, special-livery aircraft.
- Most frequent airline / family / type for each.
- Recent activity: last 5 flights, last sighting session.
- Open issues count, with a link to Issues.

## Flights

**List.** Table with date, flight number, route, airline, type, registration, distance, duration, and a track icon (recorded track or great circle only; hovering it explains which, the source, and whether the track has gaps). Filters by year, airline, airport, type. Search.

**Detail.** Map (track or great circle), all fields, the linked airframe with its other flights and sightings, findings for this record.

**Quick add (requirement F3).**
1. Enter flight number and date.
2. If a flight lookup is available ([13](13-reference-data.md)), prefill airline, airports, times, type, registration. Shown as suggestions. In practice this works only for flights in the last 10 days with an AeroAPI key, or during the flight through "capture during flight". For older flights the user types the registration.
3. Otherwise enter airports (autocomplete on IATA, ICAO, city, name).
4. Optional fields are collapsed under "More": seat, class, times, gate, livery, notes.
5. Every time field is a date-and-time input. The date part starts as the scheduled date (for landing: the date implied by the duration) and is always shown next to the time, so a takeoff after midnight is entered on the next day, not on the scheduled date.
6. Checks run as fields change; findings show inline.

## Sightings

**List.** Table with date, location, registration, operator, type, special livery, phase. Same filters and search as flights.

**Quick add (single).** Registration, then date and location (default: last used), then phase (one tap). After the registration is entered, the app shows what it knows about the airframe (type, operator, previous sightings, "you flew on this aircraft on ...").

**Session add (bulk).** For a spotting session with many aircraft: set date and location once, then add registrations one after another (type or paste a list). Each row resolves in the background; rows with findings are marked. A single session can have more than 100 sightings, so this flow matters.

**Photo link.** Optional field: paste a Google Photos share link. Shown as a plain link. (Google offers no way to embed or resolve these links.)

## Aircraft

**List.** Distinct airframes with type, current registration, operator, number of flights, number of sightings, first and last seen. Filter "provisional only".

**Detail.** Facts (MSN, first flight, type, model), registration history, operator history, timeline of the user's flights and sightings, special liveries seen.

**Tools.** Merge airframes, split a registration period, set MSN, edit facts (stored as user values, see `field_provenance`). See [11](11-aircraft-identity.md).

**Facts and their sources.** Each fact says where it came from: "from OpenSky", "from Flightradar24" (linked to the page), "from your sheet", "entered by you". "Look it up" links open airfleets.net, aviation.flights, planespotters.net and Flightradar24 with the registration filled in. "Paste from a web page" reads the serial number, line number, first flight and delivery dates from text copied off one of those pages, shows what it found and warns when the page cannot be about this aircraft (it first flew after one of the user's records); "Save these" stores the values as the user's. The list has a "No first flight date" filter for working through the gaps. See [13](13-reference-data.md), "Airframe facts".

## Airports

**Opened from** any map: clicking an airport dot, an airport label or a spotting location on the flat maps (Home, Flights, Spotting, Map, an airport page) or on the globe opens `/airports/<id>`. On a flight page, the airport names in the header and the airports on the map link there too. Hovering an airport shows its name and the number of flights in the period.

**Page.** Follows the shared period control.
- Header: the airport code, city, full name, country, ICAO code.
- Lead sentence and facts: departures, transits, landings, the airport flown with most often, aircraft photographed (sightings and days), the first day the user was there.
- A transit is a landing at the airport followed by the user's next flight leaving it within 24 hours (the next day at most when times are missing). Its two flights count as one transit, not as a landing and a departure.
- Map of the flights to and from the airport and the spotting dot; other airports on it open their own pages.
- Flights list, newest first, 20 per page, with a "Transit" pill on both legs of a transit.
- Aircraft photographed there, one row per airframe (times seen there, flights on it, last seen there), 30 per page.

## Addresses

Pages of records have readable addresses made from what the record is, not from stored ids, so an address still works after the log is rebuilt from its sources (Decided).

| Page | Address | Made from |
|------|---------|-----------|
| Flight | `/flights/2025-03-14T0830-BOS-SEA` | Local takeoff date and time at the departure airport, then departure and arrival codes. Without a takeoff time: `/flights/2025-03-14-BOS-SEA-DL300` (flight day, route, flight number if any). |
| Sighting | `/spotting/2025-03-14-BOS-N1001X/edit` | Day, place, registration: one sighting per aircraft, place and day (Q-SIGHTING-UNIT). |
| Aircraft | `/aircraft/airbus-99001` | Maker and serial number, the airframe's identity ([11](11-aircraft-identity.md)). Until the serial number is known: `/aircraft/N1001X-2024-03-01`, the registration it was first seen with and that day (what the provisional identity is made of). |
| Airport | `/airports/BOS` | IATA code, or ICAO when the IATA code belongs to another airport too. |

- Neither the flight number nor the registration is the key. Flight numbers repeat (an airline often uses one number both ways, or for a shuttle flown several times a day); no one leaves the same airport twice in one minute, so the takeoff time is. Registrations rotate when an aircraft changes hands and are reused on other aircraft; the serial number stays with the airframe.
- A sighting keeps its registration in the address: it records one moment, and the registration at that moment does not change.
- If two records would get the same address, the later one gets `-2`, `-3`.
- Addresses ignore case. Old addresses still open their page: one made from a stored id, and an aircraft address made from a registration (bare, or with the day first seen) when only one aircraft in the log carried that registration. So an aircraft's address changes once, when its serial number becomes known, and the old one keeps working.
- Editing a flight's takeoff time or route, or a sighting's day, place or registration, changes its address.

## Paging

Long lists show one page at a time, with a count ("31–60 of 330 aircraft") and page buttons (first, last and the pages around the current one). Changing a filter, the search or the period goes back to page 1. Changing page scrolls back to the top of the list.

| List | Per page |
|------|----------|
| Flights | 30 flights, grouped by month; month totals count the whole month |
| Spotting | 10 days out; a day with many sightings still shows 12 and a "Show all" button |
| Aircraft | 50 aircraft |
| Airport page | 20 flights; 30 aircraft |

## Stats

- Flights, Sightings, Combined tabs with the summaries from [24](24-statistics.md).
- Pivot builder: choose up to two dimensions, a measure, filters. Table plus chart.
- Saved views (name, dimensions, measure, filters).
- Every number shows "N left out (missing X)" when it applies.

## Map

- Flights map with filters (year, airline, type). Tracks drawn when present, great circles otherwise.
- Sightings map (spots and airports with counts).
- Export: figure (PNG/SVG) or video (MP4/WebM) for one flight, a date range or year, or all flights. See [23](23-tracks-and-maps.md).

## Import

Wizard: choose source → upload or pick file → column mapping (auto-detected for known formats) → review → commit.

Review screen:
- One row per record: parsed values, normalised values, resolved airframe.
- Findings from the deterministic checks.
- Agent suggestions if a check result was loaded ([22](22-agent-verification.md)).
- Per row: accept, edit, or skip. Per suggestion: accept or reject. Bulk accept by rule.
- Commit creates an ImportBatch. Import history lists batches with an undo button.

## Issues

All open findings grouped by rule. Each has the records involved, the suggested fix, and "accept warning" (IssueAck). A second tab lists accepted warnings so they can be reopened.

## Settings

- Display: theme (follow the device, light, dark), units, code style (IATA / ICAO / both), model naming style, family overrides.
- Data: storage adapter, sync status, last sync, conflicts to review, backups, export (JSON zip, CSV, FR24 CSV), delete all data.
- Reference: local overrides for airports, operators, types.
- Agent check: Claude Code / Codex / none; verification rules list (the "Importing prompts"); "send notes" default off.
